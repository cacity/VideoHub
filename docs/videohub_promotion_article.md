# 收藏的视频终于不再吃灰：我做了一个本地视频知识整理工具 VideoHub

你有没有遇到过这种情况：收藏夹里放了很多课程视频、技术分享、访谈节目和会议回放，但真正要用的时候，却只能重新打开视频，一点点拖进度条找内容？

视频是一种很好的信息载体，但它也有一个明显的问题：看起来方便，复用起来很麻烦。一个 1 小时的视频，里面可能只有 5 分钟对你最有价值；一个英文技术访谈，可能观点很好，但每次都要边听边理解；一套课程视频，第一次看完之后，如果没有字幕、笔记和摘要，后面复习时还是要重新从头找。

我做 VideoHub，最初就是想解决这个问题。

它不是一个单纯的视频下载器，也不是只做语音转文字的小工具。我更希望它成为一个本地视频知识整理工作台：把视频链接、本地视频、本地音频，统一变成可以搜索、可以阅读、可以归档、可以继续复用的知识资料。

VideoHub 是我最近持续整理和开源的一个本地桌面工具，项目地址：

[https://github.com/cacity/VideoHub](https://github.com/cacity/VideoHub)

![VideoHub 界面示例](https://raw.githubusercontent.com/cacityfauh-ui/MyPic/master/pic/20250923101839756.png)

## 它主要解决什么问题

很多人收藏视频，其实收藏的是视频里的信息。

比如技术课程里的一个知识点，访谈节目里的一个判断，产品演示里的一个操作流程，会议录音里的一段决策记录。这些内容如果只停留在视频里，就很难被检索、整理和再次使用。

VideoHub 想做的是把这些内容从视频里“取出来”。

一个典型流程大概是这样：

```text
视频链接 / 本地视频 / 本地音频
  -> 下载或导入
  -> 提取音频
  -> Whisper 转写
  -> 生成字幕
  -> 翻译字幕
  -> 可选 DeepSeek 润色
  -> 生成 Markdown 摘要
  -> 可选 AI 中文配音
  -> 可选烧录字幕
  -> 统一归档
```

这样处理完以后，视频不再只是一个只能播放的文件，而是变成了几类可以复用的材料：视频文件、字幕文件、转写文本、摘要文章、中文配音版本、带字幕版本。

## 场景一：整理技术课程和长视频

VideoHub 最适合的场景之一，是处理技术课程、公开课、讲座、访谈和长视频。

你可以把 YouTube、Bilibili、Twitter/X、抖音、Instagram 等视频链接粘贴进去，也可以直接选择本地视频或音频文件。程序会根据你的勾选项执行下载、转录、字幕生成和摘要生成。

如果视频有平台原生字幕，VideoHub 会优先尝试使用原生字幕；如果没有字幕，就可以用 Whisper 做语音转写。转写完成后，可以生成 `.srt`、`.vtt`、`.ass` 等常见字幕格式，也可以把转写文本整理成 Markdown 摘要。

这对于学习类视频很实用。

以前你可能需要反复看一整段课程，才能找到某个概念的位置。现在可以先看摘要，快速知道视频讲了什么；需要细节时，再通过字幕或转写稿定位到原视频片段。尤其是几十个视频组成的课程列表，这种整理方式能节省很多重复查找时间。

## 场景二：处理英文视频和双语字幕

英文视频是很多人学习技术、AI、产品、创业和学术内容的重要来源，但直接看英文长视频并不总是轻松。

VideoHub 可以把英文视频转写成字幕，并翻译成中文。最近我也给字幕翻译加了一个更实用的增强：先用 Google 翻译完成初译，再可选使用 DeepSeek 对中文字幕做轻度润色。

这个设计不是让大模型大幅重写字幕，而是解决逐句翻译常见的问题，比如：

- 同一个术语前后翻译不一致。
- 中文语序比较生硬。
- 上下句衔接不自然。
- 技术词在人类阅读时不够顺。

开启 DeepSeek 润色后，VideoHub 会同时保留 Google 初译版和 DeepSeek 润色版，方便你对比。默认情况下，后续配音和字幕烧录会使用润色后的版本。如果没有配置 DeepSeek Key，也不会影响主流程，程序会继续使用原翻译结果。

也就是说，你可以先用低成本方式快速得到中文字幕，再在需要更好阅读体验时，打开润色开关。

## 场景三：把视频变成可以阅读的笔记

很多时候，我们并不是想“看完视频”，而是想“拿到视频里的信息”。

VideoHub 的摘要功能就是围绕这个目标设计的。转写完成后，可以调用 LLM 把长文本整理成 Markdown 文稿。这个文稿可以是学习笔记、内容摘要、课程提纲，也可以作为后续写文章、做资料库、整理知识卡片的基础。

例如一个 40 分钟的技术分享，处理完成后可以得到：

- 原始视频
- 音频文件
- 字幕文件
- 转写文本
- Markdown 摘要
- 可选中文配音视频
- 可选带字幕视频

这些文件都保存在本地，不依赖云端平台。对个人学习、资料归档、课程整理和内容二次加工来说，会更安心，也更方便后续管理。

## 场景四：AI 中文配音和字幕烧录

VideoHub 现在也加入了 AI 配音流程。

默认情况下，程序使用原来的 Kokoro TTS，保留晓贝、晓晓、云健、云扬等中文音色。如果你想要更自然的本地配音效果，也可以手动切换到 CosyVoice SFT 或 CosyVoice Instruct。

![CosyVoice 样片演示](https://img.youtube.com/vi/zigNxozcGEQ/hqdefault.jpg)

样片演示：

[https://www.youtube.com/watch?v=zigNxozcGEQ](https://www.youtube.com/watch?v=zigNxozcGEQ)

AI 配音的大致流程是：

```text
视频
  -> 生成原始字幕
  -> 翻译中文字幕
  -> 可选 DeepSeek 润色
  -> 按字幕时间轴生成中文语音
  -> 合成回视频
  -> 可选压单语字幕或双语字幕
```

这个功能适合做学习预览、个人资料整理、外语视频理解辅助。它不是为了替代专业译制团队，而是把原来需要多个工具手动串联的流程，尽量放到一个本地工作台里完成。

在实际使用时，你可以先在设置里选择 TTS 后端，再到 AI 配音页选择音色。音色旁边有试听按钮，试听文件会缓存起来，同一个音色下次试听时不需要重复生成。

## 场景五：白天收藏，晚上自动处理

处理长视频很耗时间。下载、转写、翻译、摘要、配音，每一步都可能需要等待。如果所有任务都在白天手动执行，很容易打断工作。

所以 VideoHub 做了闲时队列。

你可以在白天看到有价值的视频时，先把任务加入队列；晚上电脑空闲时，再让它自动依次处理。默认可以设置类似 `23:00 - 07:00` 这样的闲时时间段。

配合浏览器扩展使用时，体验会更自然。在 YouTube、Twitter/X、Bilibili 等页面上，可以通过扩展把当前视频加入队列。桌面端本地 API 会接收任务，等到闲时时间再执行。

这对批量课程、播放列表、访谈合集尤其有用。你不需要一直盯着进度，只要提前把任务排好，第二天再看处理结果。

## 场景六：手机也能在家里本地下载视频

还有一个很实际的小功能：手机本地网页下载。

有时你在 iPhone 上看到一个视频链接，但 VideoHub 是桌面软件，手机上不能直接运行。为了解决这个问题，项目里加了一个轻量网页端。

在电脑上启动本地网页服务后，手机和电脑连接同一个 Wi-Fi，就可以用手机浏览器访问局域网地址。页面只保留最核心的操作：粘贴链接、触发下载、下载完成后打开或保存。

启动方式：

```bash
python src/mobile_web_server.py
```

终端会显示类似 `http://局域网IP:8787` 的地址。手机访问后，把视频链接粘贴进去即可。下载文件会保存在电脑本地目录，手机端也可以通过 Safari 的分享菜单保存到相册。

这个功能不是云端服务，而是家庭局域网里的本地辅助入口。它的重点是方便自己在手机上临时处理视频链接。

## 它能带来哪些方便

对我来说，VideoHub 最大的价值不是某一个单独功能，而是把原来分散在多个工具里的流程串起来。

以前处理一个视频，可能需要这样做：

```text
复制链接
打开下载工具
下载视频或音频
打开 FFmpeg 提取音频
打开 Whisper 转写
找字幕工具生成字幕
找翻译工具翻译字幕
再找大模型整理摘要
如果要配音，还要再找 TTS 工具
最后再用 FFmpeg 合成视频
```

这些工具都很好，但来回切换很消耗精力。VideoHub 想做的是把这些步骤放到一个可操作的桌面界面里。你只需要根据任务勾选选项，剩下的流程交给程序。

它带来的方便主要有几个：

- 视频内容可以搜索，不用反复拖进度条。
- 英文视频可以变成中文字幕和中文摘要。
- 长视频可以压缩成可阅读的 Markdown 笔记。
- 批量视频可以排队处理，不需要一直手动盯着。
- 本地资料、在线视频、手机链接可以进入同一套整理流程。
- 字幕、转写、摘要、配音、成片文件统一保存在本地目录里。

## 技术实现上做了什么

VideoHub 是一个 PyQt6 桌面应用，核心处理逻辑主要由 Python 代码串联起来。

目前主要用到：

- PyQt6：桌面图形界面。
- yt-dlp：处理多平台媒体下载。
- FFmpeg：音视频提取、合成和字幕烧录。
- Whisper：语音转文字和字幕生成。
- Google 翻译：基础字幕翻译。
- DeepSeek / OpenAI：摘要生成和可选字幕润色。
- Kokoro / CosyVoice：中文 TTS 配音。
- Flask：本地 API 和手机网页入口。

项目的重点不是炫技，而是减少重复操作。很多功能并不复杂，真正麻烦的是把它们稳定地串成一个工作流，并且处理好目录、文件名、队列、异常、配置和回退逻辑。

## 使用边界

VideoHub 不是万能下载器，也不是绕过平台规则的工具。

不同平台对视频访问、Cookie、登录态、版权、下载和批量处理都有自己的限制。使用时应该只处理自己有权处理的内容，遵守平台条款和相关法律法规。

另外，一些功能依赖本地环境，比如 FFmpeg、Whisper、TTS 模型、DeepSeek Key、OpenAI Key 等。没有配置对应环境时，相关功能会受限，但不影响其它基础流程。

我更愿意把它定位为一个本地视频知识整理工具：帮你把已经合法获取和有权处理的视频内容，整理成更容易阅读、检索和复用的资料。
