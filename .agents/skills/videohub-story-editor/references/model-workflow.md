# 模型无关的故事理解流程

这套流程适用于 Codex、Claude Code、DeepSeek 或其他具备足够上下文能力的模型。
模型输出必须遵循 `story-analysis-schema.md`，不得把供应商特有字段带入后续计划。
外文视频的前三个阶段只以原文字幕为内容证据；基础翻译和润色放到剪辑计划确定之后。

## 第一阶段：分块理解

逐个提交 `analysis_chunks/chunk-*.json`。系统指令应包含：

```text
你正在分析长视频的一个时间分块。只依据提供的字幕、场景和已检查的关键帧作答。
提取人物或说话人变化、事件、观点、问题与答案、教程步骤、结果、指代和未解决信息。
每项判断必须保留证据 ID。不要在这个阶段推断整部视频结论。
```

保存每个分块的结构化结果。不得只保存自然语言摘要，因为后续需要回到精确证据。

## 第二阶段：全局理解

向模型提供：

- 所有分块结果。
- `evidence_pack.json` 的目录信息和统计。
- 已检查的关键帧观察。
- 内容类型策略。

系统指令应包含：

```text
综合所有分块，建立全片人物或说话人、事件时间线、观点结构、因果关系、主题、
连续性约束和不确定性。时间先后不等于因果。字幕不能证明的画面信息不得补写。
提出一到三个有证据支撑的短故事方案，并选择一个方案。
只输出符合 Story Analysis 1.0 的 JSON。
```

## 第三阶段：剪辑草案

向模型提供已校验的 `story_analysis.json`、选中方案和相关证据条目。系统指令应包含：

```text
为选中的故事方案生成剪辑草案。每个片段必须引用 analysis_refs，并使用源视频时间。
保留完整句子和必要上下文。可以重排，但不得改变事实、因果、人物关系、教程步骤、
问题与回答关系，或制造说话者未表达的观点。视觉片段必须引用已检查的视觉证据。
不要计算输出时间轴，不要编写 FFmpeg 命令。
```

输出 `story_plan.draft.json`，再交给 `compile_story_plan.py` 计算最终计划。

## 第四阶段：最终字幕翻译

编译并校验剪辑计划后，先重建最终原文 SRT。翻译模型看到的上下文应按成片顺序
排列，不再按原视频顺序排列。轻度润色只处理译文的术语、指代、语气和跨句衔接，
不得改动序号、时间码、事实含义或字幕条目数量。

## 第五阶段：解说文案

只在用户请求 TTS 解说版时执行。向模型提供 `story_analysis.json`、
`story_plan.json`、`story_source_map.csv` 和已选证据，系统指令应包含：

```text
为同一剪辑计划编写中文解说。每个解说块使用最终成片时间轴，并引用支持它的事件、
字幕、视觉或剪辑片段 ID。可以概括和连接事实，但不能虚构原片没有提供的情节，
不能把编辑判断伪装成原片对白。给重要原声对白和环境声留出空间，文字密度控制在
自然中文语速范围。只输出符合 Narration Plan 1.0 的 JSON。
```

模型输出先由 `validate_narration_plan.py` 校验，再调用 MiniMax 或豆包。TTS 供应商
只接收已经校验的单块文案，不参与故事理解或事实判断。

## 上下文控制

- 默认每个分块约 300 秒，可根据字幕密度缩短。
- 分块跨界字幕可同时出现在相邻分块，使用字幕 ID 去重。
- 全局阶段提交分块结构化结果，不重复提交全部原始字幕。
- 选段阶段只加载候选故事涉及的字幕和视觉证据。
- 模型上下文不足时增加分层汇总，不删除证据引用。

## 无视觉模型时

- 保留 `visual_findings` 为空数组。
- 在 `uncertainties` 中说明画面尚未检查。
- 不自动选择 `visual` 片段。
- 仍可为播客、访谈和演讲生成仅由对白构成的计划。

## API 失败

外部分析模型未配置、超时或返回无效 JSON 时，不影响 VideoHub 现有下载、字幕、
翻译和配音功能。保留证据包并停止在故事理解层，等待当前 Agent 或其他模型继续分析。
DeepSeek 润色或 TTS 供应商失败时，分别保留基础翻译和原声版，不回滚上游产物。
